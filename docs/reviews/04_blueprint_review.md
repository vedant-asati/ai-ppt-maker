# Engineering review of the Unified Presentation Agency Blueprint

**24 November 2026 · Reviewed revision `44ab332` · Revise before adopting as the implementation specification.** [Blueprint under review](../unified_presentation_agency_blueprint.md) · [Previous project review](03_project_review.md)

The blueprint makes a sound product choice. A presenter should be able to defend a number, find its source, correct it once, and hand off a deck they can still edit. Stable slide identities, explicit abstention, and a shared layout vocabulary all serve that goal. The approval is premature because the proposed acceptance tests can pass while the presenter still receives a false claim, a duplicated slide, or a file containing private notes. Each of those has a concrete failure path in this checkout.

I would fund one end-to-end slice first. Give the system a local quarterly report, generate a short board update, let a reviewer correct a metric, then export a PDF and an audience-safe, editable PPTX. Require the reviewer to find the supporting passage, distinguish a forecast from an actual, and verify the correction in both files. This exercises the most valuable part of the proposal at lower cost than building five subsystems in parallel.

## 1. Specify what a grounded claim means

**A foreign key can prove the source exists. It cannot prove the source supports the sentence.** The proposed `EvidenceItem` holds a URL, snippet and extracted strings. `MetricBinding` holds a value, unit and one ID. Neither records which entity, period, denominator, comparator, direction or actual/forecast status the assertion concerns. Even the blueprint’s exemplary executive headline joins two metrics with a relationship. Verifying each number separately leaves that relationship unexamined. Similarly, changing “approved” to “proposed” can change a decision without changing a single number.

Start with source spans and a small typed claim record. Support local PDF pages, table cells, user-supplied figures and versioned web passages. Keep an exact value and scale, source revision, locator, dimensions, and review state. A calculated margin needs two inputs and a reproducible formula. An explicitly labeled forecast needs an assumption owner and period. A conflicting or superseded source needs a visible resolution. Permit multiple passages to support one claim and one passage to support several claims. A local confidential report can use a private locator while an external deck uses an approved public label. Token overlap can retrieve candidates. Accepting an assertion needs an independent support check or a recorded human decision. [Current citation model](../../ppt_maker/core/schemas.py#L151) · [Research synthesizer](../../ppt_maker/research/synthesizer.py)

**Make abstention survive the entire pipeline.** Pass distinct states for zero, missing, estimated, contradicted and approved. Validate claims after extraction, editing, fallback and refinement, then compare them with the visible PDF text and PPTX shapes. Include headings, chart axes, deltas, labels, captions and qualitative cards. Otherwise a missing KPI can reappear as “high impact” or “verified” without evidence. For long documents, retrieve the relevant table with its headers, units and footnotes together. Test with the decisive qualification on the final page. The architect currently takes the first 4,000 characters of source text. [Architect input](../../ppt_maker/planning/multi_agent/stages.py#L248) · [Refinement](../../ppt_maker/planning/refiner.py#L227)

The same rule applies to artwork. A generated photo labeled as an installed facility or a chart drawn by an image model can make a factual assertion that never appears in a text field. Mark illustrations as such and render evidence-bearing charts from the checked data series. Keep retrieved passages in a data-only input to the planner. A quoted instruction inside a source should have no authority to change the audience, send a confidential figure to an image provider, or mark a claim approved. Record which stages may access each source and test disconnected replay with those permissions enforced.

**Acceptance exercise.** Seed a report with a genuine zero, conflicting periods, a figure in thousands, a forecast and an unsupported causal explanation. Put the exact source after two near matches. Require correct visible values, auditable derivations, and an explicit unanswered item. Measure both false support and how many supported claims survive. A system that abstains on every slide can otherwise score perfectly. Use independent reviewers for ambiguous entailment and show the denominator behind any published rate.

## 2. Give each slide, revision and export a clear owner

The example calls `sld_` plus eight hex characters a UUID. It retains 32 random bits and the prefixed value is invalid for a UUID-typed field. The practical risk depends on scope. Twenty slides in one isolated deck have a tiny collision probability. At 10,000 independently issued IDs in a shared namespace, the birthday estimate is about 1.16%. Use a full persisted ID, enforce uniqueness in its declared scope, and track display order separately. On first import of a legacy numbered plan, persist the migration once. Reordering should preserve identity, duplicating a slide should allocate a new identity, and rerolling should create a new revision of the same slide. [Identity proposal](../unified_presentation_agency_blueprint.md#pillar-5-stable-identity-ephemeral-sandbox--144-dpi-cdp-telemetry) · [Current renumbering](../../ppt_maker/planning/validator.py#L65)

A per-run directory addresses filename contention. It still leaves decisions about shared image caches, final output paths, cancellation and two writers editing the same deck. Define a manifest containing the requested ordered slide IDs and revisions, plan and asset hashes, required outputs, and terminal status. Verify exactly one current artifact per requested ID and format, inspect the merged outputs, then publish the set together. Include the native master-template route. Keep the last successful deliverable if a retry fails. Preview needs its own output namespace even when the input already has three slides. A useful failure drill interleaves two runs, drops the middle plate, repeats the first, then interrupts the last export. [Image cache](../../ppt_maker/imaging/image_cache.py) · [Compilation paths](../../ppt_maker/cli.py#L580) · [Native template injection](../../ppt_maker/export/template_injector.py)

**Treat privacy as a delivery decision.** The fixed HTML templates can hide speaker notes on screen while the PPTX deliberately includes them in its notes parts. Disabling the Markdown notes sidecar does not suppress those parts. Presenter notes, raw source passages, internal links and refinement traces each need a destination and retention policy. Provide separate presenter and audience deliverables. Test the latter with a private sentinel in the input and inspect the files actually sent, including notes parts, relationships and bundled assets. Define who can view or delete retained source material before exposing a hosted canvas. [PPTX notes writer](../../ppt_maker/export/pptx_exporter.py#L229) · [CLI notes option](../../ppt_maker/cli.py#L607) · [Microsoft’s PresentationML package structure](https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document)

## 3. Prove the visual and editing contract on a real slide

The proposed geometry conversion is correct for its ideal canvas. On a 1,920-wide design mapped to 13⅓ inches, 1 CSS pixel corresponds to 6,350 EMUs. At 960 pixels across the same physical canvas it corresponds to **12,700 EMUs** if the design actually scales to that width. Today the split template itself declares 1,920 × 1,080, the preview viewport halves those dimensions, and the PPTX declares a width of 13.333 inches. Derive coordinates from the measured slide root and the actual target dimensions, subtract the root origin, and round once. A 48 CSS-pixel font at the full design scale corresponds geometrically to 24 PowerPoint points. Passing the raw CSS number as points doubles it. [Split canvas](../../ppt_maker/templates/split.html#L6) · [PowerPoint slide dimensions](../../ppt_maker/export/pptx_exporter.py#L33)

A DOM bounding rectangle describes the element’s box. It does not specify where editable text will wrap in PowerPoint. The sample records size, weight and color while omitting font family, padding, paragraph spacing, line breaks, direction, transforms and shape margins. A parent card rectangle is also ambiguous when two child metrics need independent selection. Define stable slot instances and supported editability per element. Measure after fonts and images settle, before concealing any text. Test a narrow multiline title, reverse split, RTL text, missing font, and a longer edited value. Compare rendered output in a named Office client, with a tolerance and an accessible reading order. Even the referenced products document font substitution and trade-offs for editable elements. [CSSOM bounding rectangles](https://www.w3.org/TR/cssom-view-1/#dom-element-getboundingclientrect) · [Pitch’s PowerPoint export support](https://help.pitch.com/en/articles/6713988-export-a-presentation-to-power-point)

The proposed plate selector would cause two different defects on the same slide. Hiding `.slide-content` removes the split template’s **image and card**, which both live inside that subtree. The base template places the **footer and citations outside** it, where they can remain burned in beneath native overlays. Blanket SVG text stripping can also delete axis labels with no replacement. Declare each semantic element as native editable content, retained artwork, or decoration, then verify it appears exactly once. For the board scenario, decide whether “editable” includes changing a chart's underlying data. A title overlay on a screenshot cannot satisfy that task. [Split markup](../../ppt_maker/templates/split.html#L128) · [Footer and citation markup](../../ppt_maker/templates/base.html#L877) · [Current capture](../../ppt_maker/rendering/renderer.py#L250)

The layout registry is worth building once those responsibilities are clear. Consolidate template selection, permitted block types, slot cardinality and target capabilities. Remove competing coordinate authorities by specifying when measured geometry supersedes a declared fallback. A new semantic block can legitimately require a schema, exporter and compatibility tests. Replace the “exactly two files” target with a contract test that fails when a supported slot disappears, duplicates or loses editability in any advertised format. Character budgets can guide generation. Rendered fit and preservation of meaning should decide acceptance. [Slide and block schemas](../../ppt_maker/core/schemas.py) · [Layout validation](../../ppt_maker/planning/validator.py) · [Template dispatch](../../ppt_maker/rendering/templater.py#L72)

## 4. Separate presenter preferences from release gates

| Presenter | Counterexample to the proposed rules | Better acceptance task |
| --- | --- | --- |
| Board presenter | A short, approved title such as “Cash flow” and a mandatory reconciliation table can violate headline and layout-rhythm rules. Adding a decorative interlude makes comparison harder. | The reviewer can reconcile one figure to its source and correction, and the reader can identify the decision and unresolved risk. |
| Founder | A 92-point headline may fit the English pitch and wrap over its edited German translation. A partner also needs to update the funding ask after handoff. | Edit and reopen the ask on a supported PowerPoint client, then inspect wrapping, margins and ownership of visual objects. |
| Architect | A sequence diagram may need stable labels across three consecutive detailed slides. A forced takeaway can imply a migration outcome still under evaluation. | An engineer can trace a dependency and distinguish the proposed state from the deployed state. An audience copy contains no internal presenter instructions. |
| Research analyst | Multiple sources can disagree on a denominator. A link badge and a single-source rule conceal that disagreement. | The reader can identify the definition, date, conflicting source and rationale for the stated conclusion. |

Use answer-first titles, rhythm and surface ratios as selectable editorial defaults. Treat changes to approved titles as suggestions the author can inspect. The blueprint gives Hero titles a 65-character limit and later allows 80 in its narrative validator. It also uses a 64–92 pt Hero clamp in one section and 92–110 pt in another. State which policy wins per audience, language and layout. Measure the time to a defensible handoff and the corrections a presenter must make against their ordinary template workflow. Slide variety alone cannot establish that an additional planning agent earns its latency and spend.

For contrast, the cited thresholds correspond to WCAG’s enhanced **text contrast** criterion, with the lower ratio conditional on large text. The word “headline” does not establish the size. A 94% scrim, blur, or 60–30–10 ratio cannot guarantee the result for an arbitrary text color. Inspect foregrounds against the composited surface, including footnotes and text crossing images. Verify meaningful reading order, alternative text and chart distinctions independently. Report projector legibility as a separate viewing test. [W3C explanation of enhanced contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-enhanced.html)

Procedural textures are a reasonable way to retire extracted imagery. The four examples cover only part of the nine mapped themes. Build and install a candidate wheel, open every legacy theme from a clean directory, inventory assets and attribution, and record compressed wheel size separately from installed dependencies and browser size. Measure cold and warm print time, memory, output file size and rendered detail with each filter enabled and disabled. A data URI still needs decoding and rendering, and the PPTX plate is raster by design. Removing one asset family also leaves font, artwork and example-deck provenance to verify independently. [Theme mapping](../../ppt_maker/design/theme_resolver.py) · [Packaging baseline and provenance review](03_project_review.md)

## 5. Change the build order and the release decision

| Order | Decision to fund | Evidence required to advance |
| --- | --- | --- |
| 1. Establish the baseline | Engineering owns the zero-value, wrong-source, duplicate-plate and preview cases above. Product selects the board-update workflow and one supported PowerPoint client. | Reproducible fixtures with expected claims, IDs and output pages. Record current correction time, unsupported assertions, preview duration and provider usage where measured. |
| 2. Ship one trustworthy workflow | Carry source spans, claim status and immutable slide identity through two layouts, preview, edit and export. Make audience-safe delivery and manifest verification part of this slice. | A presenter corrects a figure once. Both files show the same approved claim, destination and slide order. Injected duplicate, missing and stale artifacts block publication. An audience copy passes private-content inspection. |
| 3. Expand the registry and editing controls | Migrate legacy plans and measure compatibility. Add reroll with locked author edits, explicit image regeneration and undo. Define replay of approved content separately from byte-identical rendering. | Replay uses recorded theme, layout, assets and fonts. Run a disconnected test. A reroll preserves unrelated slide revisions and bills only the requested generation work. Shared evidence and headline dependencies are revalidated. |
| 4. Validate economics, then widen distribution | Run paired single-shot and staged evaluations on the same source dossiers early. Measure model/version, tokens, elapsed time, repair attempts, semantic accuracy, and human editing time. Gate new visual targets and hosted UI on demonstrated demand. | Publish per-case outcomes and failures, disclose fallbacks, and name the sample size. Benchmark preview separately for cold launch, cached replay and new planning, with requested outputs specified. Adopt a latency target after measuring a distribution. [Current comparison uses fixed token inputs](../../evals/compare_pipelines.py#L231) |

An instantaneous three-slide preview needs a defined starting point. The CLI currently plans before slicing, so a fresh topic and replayed plan have different costs. The implementation calls the plan-saving option `--dry-run`, while the blueprint calls it `--plan-only`. Define aliases or migration, the expected page count as `min(3, deck length)`, the maximum permitted external calls, and which files may be written. For replay, specify whether an explicit override wins, how missing fonts/assets are reported, and whether auto-refinement may change approved copy. For reroll, use the deck revision to resolve a display number and preview any changes to shared claims. [CLI options](../../ppt_maker/cli.py#L113) · [Generation order](../../ppt_maker/cli.py#L369)

Finally, choose a canonical specification. The indexed blueprint has **356 lines** and a **252-line** roadmap copy carries a different set of instructions. All four opening cross-references in the indexed file miss their targets, and its “docs/README.md” link resolves to the repository README. The consensus record gives message numbers but no linked performance experiment, source-to-claim ledger, or presenter trial. Keep the authors’ rationale, label unmeasured targets as hypotheses, and assign a named decision owner to each release gate. An implementer should be able to tell which promises they can rely on today. ### Verification scope

The checks used the local virtual environment and a scratch copy of tracked project files at the reviewed revision. The citation test mocked research and planning and executed the public CLI. Normalization and recovery probes invoked the relevant functions directly. The preview used real Chromium, system fallback fonts, local imagery, PDF parsing and PPTX reopening. The duplicate-plate test reused its actual images. The wheel was built without dependency downloads. The review did not run the full test suite, paid inference, a native PowerPoint rendering session, a projector trial, or a presenter study. The rates, cost thresholds and native fidelity gates above are proposed measurements.
