# AI Presentation Agency 4.1.0 Code Review

**23 November 2026** · Reviewed `c39514b` against the preceding review baseline, `ee1dc2e`.

Version 4.1.0 adds a Cloudflare image provider, theme textures, cover imagery, and a common Gemini Flash-Lite model across planning stages. Keep the typed `MasterPlan` and deterministic rendering pipeline. Before releasing, address the credential exposure, bound planner retries, and verify the image and slide artifacts the CLI reports as complete.

## Release blocker

### P0 Credential-shaped values in the tracked environment example

`.env.example` lines 12–14 contain three populated Gemini key assignments in the local commit history. The local `origin/main` tracking snapshot contains placeholder values and no matching credentials. That snapshot cannot establish whether the values were shared elsewhere. Treat any real credentials as exposed, revoke or rotate them and check project usage, replace the values with placeholders, and remove the credential-bearing history before publishing the branch. Credential validity was deliberately left untested.

## Findings in the latest changes

### P1 Planner retries can block a generation for hours or days

The single-shot planner raises the attempt limit to `max(6, key_count * 2)` while retaining exponential delays with no cap or overall deadline. A mocked persistent 503 with one key made six requests and scheduled 155 seconds of sleep, up from 35 seconds under the previous four-attempt limit. A mocked JSON failure with nine keys made 18 requests and scheduled 655,355 seconds of sleep, about 7.6 days, before counting request latency. A persistent 429 with two keys also scheduled a six-second wait after the final attempt. Gemini applies limits per project, so switching between keys from the same project does not reset its quota. Set a total deadline, cap per-attempt delays, honor provider retry hints, and budget provider retries separately from output repair. [Planner retry loop](../../../ppt_maker/planning/planner.py#L425) · [Gemini API rate limits](https://aistudio.google.com/docs/rate-limits#how-rate-limits-work)

### P1 Cloudflare can cache unreadable output as a successful image

The adapter accepts HTTP 200 and a base64 field, writes the decoded bytes to a `.png` path, and reports success without decoding an image. A mock response containing plain text encoded as base64 recorded `api` on the first run and `cache` on the next. Pillow rejected the file. Cloudflare's example uses JPEG, so valid output can also have a mismatched extension. The current test only checks the return value and file existence. Decode and validate the image before replacing the cache file, normalize its format or preserve its real extension, and test invalid payloads and fallback. `requests` is a direct import but currently arrives transitively through the installed Gemini SDK. Declare it directly or reuse a declared HTTP client. [Cloudflare adapter](../../../ppt_maker/imaging/image_generator.py#L379) · [Cache check](../../../ppt_maker/imaging/image_cache.py#L43) · [Provider tests](../../../tests/test_cloudflare_image.py#L16) · [Project dependencies](../../../pyproject.toml#L16) · [Cloudflare FLUX model contract](https://developers.cloudflare.com/workers-ai/models/flux-1-schnell/)

### P1 Six of nine theme textures fail to resolve from a clean checkout

All nine mapped files exist under `ppt_maker/assets`, but six default palettes already contain a relative `--bg-texture` URL. The resolver skips its package-relative lookup whenever that token is present. From generated HTML in a root-level build directory, those six URLs resolve under the top-level `assets/` directory and point to missing files. The three themes that produce absolute URLs work locally, but the dry-run plan stores those URLs. A subsequent theme change from modern proposal to digital nostalgia retained the old texture in a local check. The 4.1.0 wheel contains 16 HTML templates and zero theme assets. Store a portable texture identifier in the plan, resolve it at render time from packaged assets, and assert that the URL in generated HTML points to a real file in both checkout and installed-wheel tests. [Default palettes](../../../ppt_maker/design/theme_palettes.py#L317) · [Texture resolver](../../../ppt_maker/design/theme_resolver.py#L180) · [Plan serialization](../../../ppt_maker/cli.py#L431) · [Wheel package data](../../../pyproject.toml#L42)

### P1 Mandatory cover art expands provider calls without a working opt-out

Validation now forces imagery for covers that request none and assigns `background` or `supporting` to newly enabled cover and split slides. The image loop still runs when `generate_images: false` and `skip_image_generation: true` are both present. A one-slide mock made a Cloudflare request with both flags set. `--offline-plan` skips planning and still enters the image stage, so a saved plan can incur a new provider call and send a prompt externally. Apply a single explicit provider policy before image matching, image generation, and LLM refinement. Use deterministic local art when inference is disabled. [Cover and split validation](../../../ppt_maker/planning/validator.py#L129) · [Configuration fields](../../../ppt_maker/core/config_manager.py#L52) · [CLI image stage](../../../ppt_maker/cli.py#L473) · [Provider selection](../../../ppt_maker/imaging/image_generator.py#L259)

### P1 Release claims exceed the current evaluation evidence

On this revision, the checked-in benchmark command produces **nine synthetic wins and one tie**, versus the published ten wins. The 96.3 versus 95.0 composite scores reproduce. The deterministic scorecard independently reports **90% pass rate and 95.0/100**, versus the README's 100% and 94.1/100. These runs use synthetic plans and empty DOM audit results. The reported cost is derived from fixed token counts. The live evaluator still calls an unsupported `Planner` constructor, and the comparative harness uses its `--model` setting for scoring metadata without passing it to the planners. Label the published results as fixture results, run actual generation and rendering before claiming a planner win, and record model, latency, token usage, fallback mode, and final-artifact metrics per run. [README scorecard](../../../README.md#L130) · [Published comparison](../../evals/multi_agent_vs_single_shot_benchmark.md) · [Comparison harness](../../../evals/compare_pipelines.py#L196) · [Evaluation runner](../../../evals/run.py#L257)

### P2 The visual blueprint mixes shipped behavior with future work

The live image path is user-provided or cached imagery, Cloudflare, Gemini, then procedural gradients, with some low-priority slides using gradients directly. Hugging Face and Pexels appear in the design blueprint as part of the implemented chain. The release notes also name `VisualDirector` and `DesignThemer`, while the actual staged pipeline uses `DeckArchitect`, `BatchedSynthesizer`, and a deterministic gatekeeper. The repository has no recorded run that substantiates its Cloudflare latency and whole-deck speed figures. Document the active stages, label proposed providers as future work, and attach a reproducible benchmark to performance claims. Cloudflare publishes a daily free allocation and model pricing by tiles and steps.
