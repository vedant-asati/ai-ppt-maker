## Release blockers

### P0 Artifact completeness and identity failures

**Reproduced.** The public CLI accepted vector pages for slides 1 and 3 of a four-slide plan, produced a two-page PDF, and printed `Done`. With the corresponding PNG list, PPTX placed slide 2's text over slide 3's background. A one-slide native template accepted a four-slide plan and reported success with one slide. Real Chromium also showed that a missing HTML file yielded three PNGs and only two vector PDFs in a three-input navigation probe. The PNG audit and vector paths handle missing pages differently. [CLI compilation](../../../ppt_maker/cli.py#L561) · [PPTX position-based mapping](../../../ppt_maker/export/pptx_exporter.py#L203) · [Template capacity](../../../ppt_maker/export/template_injector.py#L78) · [Navigation handling](../../../ppt_maker/rendering/renderer.py#L80)

**Acceptance.** Attach the stable slide ID when rendering starts and carry it into every export. Reject missing, repeated, wrong, or extra IDs before marking a run complete. Validate artifact counts and report actual output paths. A fault on the middle slide must produce a clear failure or explicit degraded result, with correct metadata for every emitted slide. Cover an undersized master and locked output paths in the same regression family.

### P0 Hero Statement with subtitle crashes PowerPoint export

**Reproduced with the public CLI and real Chromium.** A valid six-slide plan with a Hero Statement subtitle wrote its PDF and notes, then crashed before creating PPTX with `KeyError: 'body'`. The exporter references a font-size key absent from its size map. Removing only the subtitle let the control deck export. The current layout tests check emitted HTML and position registration but never exercise the subtitle branch in PPTX. A separate source-content issue surfaced in the same fixture: the valid Hero Statement block holding `47%` disappeared from both visible formats. [Hero PPTX branch](../../../ppt_maker/export/pptx_exporter.py#L303) · [Hero HTML content](../../../ppt_maker/templates/hero_statement.html#L99) · [Layout tests](../../../tests/test_slidesgo_layouts.py#L74)

**Acceptance.** Export a Hero Statement with title, subtitle, badge, and notes through the real CLI and inspect the resulting PDF and PPTX. Define which content belongs on a Hero Statement. Reject incompatible blocks, move them to notes with visible accounting, or choose another layout that can present them. Route unsupported combinations to typed diagnostics rather than silently dropping them.

### P0 Unsupported numbers and unrelated citations look authoritative

**Reproduced.** A supplied citation about 14 units existed in the research fixture, but the CLI attached sources about 10 and 70 units to that slide. Both tested claim-to-source pairings were wrong. The staged recovery fixture produced `3.5x`, `92%`, `98%`, and `$12M` without evidence. Rendering a legacy KPI slide from a text-only bullet yielded `25%` and `+12% YoY` even with no model call. Model normalization can add further invented metric defaults. The normal research entry point passes no model client to `ResearchAgent` and processes search results as snippets. A search result or domain is evidence of discovery, with claim verification still required. [CLI research](../../../ppt_maker/cli.py#L333) · [Positional citation assignment](../../../ppt_maker/cli.py#L397) · [Recovery](../../../ppt_maker/planning/multi_agent/fallback.py#L124) · [Metric normalization](../../../ppt_maker/planning/multi_agent/stages.py#L116) · [KPI rendering](../../../ppt_maker/templates/kpi_dashboard.html#L123)

**Acceptance.** Require a typed value and explicit evidence IDs for evidence-driven numbers. Attach sources to individual claims upstream and preserve those bindings through rendering and editing. Replace numeric fallbacks with a missing-evidence state or a nonnumeric layout. Retest the same facts in a different slide order, a conflicting-source case, and provider failure. Confirm final PDF links and PPTX evidence, including title, number, units, and caveats.

### P0 Templates can expose speaker notes and add visible instructions

**Reproduced in the rendered PDF.** A Bento slide with a valid `BentoBlock` rendered a note marker on the slide and added a generic action absent from the supplied content. The template assigns its selected block inside a Jinja loop and then reads the outer variable. In this case it fell through to the generic branch. The PowerPoint rendition used the supplied cards without the added copy. Source inspection found visible speaker-note substitutions in creative, modern tech, and editorial templates as well. This can publish internal delivery notes as slide copy even when a user inspects the plan and believes notes are separate. [Bento block selection](../../../ppt_maker/templates/bento.html#L194) · [Bento fallback](../../../ppt_maker/templates/bento.html#L287) · [Creative](../../../ppt_maker/templates/creative.html#L125) · [Modern tech](../../../ppt_maker/templates/modern_tech.html#L122) · [Editorial](../../../ppt_maker/templates/editorial.html#L128)

**Acceptance.** Make visible strings derive from explicit visible fields and fixed design labels. Put note-only sentinels in regression fixtures and assert they never appear in PDF text or visible PPTX text. Assert that the expected card arrangement renders from the typed block, including an absent optional side card. Do not fill an empty action slot with advice the source did not provide.

### P0 Publication review for credential history and bundled media

**History confirmed.** The current `.env.example` and local `origin/main` tracking snapshot have no matches for the three previously reported credential-shaped values. Nine commits in the intended publish range still contain those assignments. ## High-priority findings

### P1 Preview exports different subsets and changes the page geometry

**Reproduced with Chromium.** A six-slide control requested preview with PPTX. It returned six PDF pages at about 1440 × 404 pt, three PPTX slides, and six note entries. The PDF split the three input slides across pages. Full rendering returned six 1440 × 810 pt pages. Preview also generated all six HTML files and processed the full deck's image needs before slicing. Background rendering uses the 1920 × 540 preview viewport and then inserts the captured image onto a 16:9 PPTX page. That capture and page have different aspect ratios. [CLI preview slice](../../../ppt_maker/cli.py#L475) · [PDF geometry](../../../ppt_maker/rendering/renderer.py#L185) · [PPTX background viewport](../../../ppt_maker/rendering/renderer.py#L261)

**Acceptance.** Compute the preview slide subset once, before expensive stages, and use it for the preview PDF, PPTX, notes, audit and numbering. Keep a 16:9 composition and scale the preview capture. A four-or-more-slide input should yield exactly three complete preview pages if that is the advertised contract.

### P1 Reverse split and citation metadata diverge between formats

**Reproduced.** On the reverse split, Chromium positioned the text at x ≈ 1184 px and the image at x ≈ 70 px. The PPTX put the editable title at 0.8 inches from the left regardless of orientation. PDF retained the test citation as a link. The corresponding PPTX slide contained no native text hyperlinks and no citation badge text. Existing `data-pptx-target` attributes can help build a geometry contract, or the supported variant set can be narrowed explicitly. [Split CSS and markup](../../../ppt_maker/templates/split.html#L15) · [PPTX split coordinates](../../../ppt_maker/export/pptx_exporter.py#L54) · [Generic overlay path](../../../ppt_maker/export/pptx_exporter.py#L334) · [HTML citations](../../../ppt_maker/templates/base.html#L883)

**Acceptance.** Default and reverse split must keep their intended text and image sides in both formats. Export citations as editable linked PowerPoint elements or clearly report the supported limitation. Inspect the artifact, including editability, against the plan.

### P1 Planner adapters disagree on evidence, slide count and layouts

**Reproduced with captured SDK requests.** A sentinel beyond character 4,000 reached the single-shot prompt and disappeared from both staged prompts. Batch synthesis accepted IDs `[1, 1]` for the expected two distinct slides. The architect's hard-coded vocabulary rewrote `hero_statement` to `bento`, and blueprint normalization returned two slides for a target of three. The programmatic `plan_presentation(num_slides=3)` wrapper writes `target_slides`, while its recipient reads `slide_count`. The mock prompt asked for approximately ten slides at the default duration. The topic argument was also absent from the captured prompt. Static inspection found that staged input handling tries to read PDF/media as text and ignores read errors. [Programmatic wrapper](../../../ppt_maker/planning/planner.py#L277) · [Blueprint normalizer](../../../ppt_maker/planning/multi_agent/stages.py#L28) · [Architect input](../../../ppt_maker/planning/multi_agent/stages.py#L240) · [Batch response handling](../../../ppt_maker/planning/multi_agent/stages.py#L424) · [Staged ingestion](../../../ppt_maker/planning/multi_agent/orchestrator.py#L31)

**Acceptance.** Normalize requests and supported source formats before planner choice. Pass relevant source excerpts and IDs into batches. Require every expected ID exactly once or recover that explicit ID. Test the programmatic path and CLI with the same count and source, including a Hero Statement blueprint and a late-source claim.

### P1 Offline behavior and configuration are inconsistent

**Partially remediated.** `--skip-images` prevented a mocked Cloudflare generation request. The equivalent nested `image_preferences.generate_images: false` and `pipeline.skip_image_generation: true` still made a request with both a dictionary and `AppConfig`. The check looks at top-level fields. Smart matching is earlier in the flow and can still use Gemini when it has a key. Without a Gemini key, matching can fall through an uninitialized `self.api_key` to the error handler, losing its PIL matching path. `--offline-plan` can also be combined with research, uses model refinement unless separately disabled, and emits a remote Google Fonts import without a local bundle. Several pipeline config fields have declarations but no normal CLI wiring. [Image preferences](../../../ppt_maker/imaging/image_generator.py#L145) · [Smart matching](../../../ppt_maker/imaging/image_generator.py#L194) · [Research ordering](../../../ppt_maker/cli.py#L333) · [Configuration](../../../ppt_maker/core/config_manager.py#L52) · [Font imports](../../../ppt_maker/templates/base.html#L7)

**Acceptance.** Resolve one typed configuration, distinguish replay from true offline mode, and enforce the latter at every network boundary. Run an offline fixture with provider mock assertions, a local font bundle, and browser request accounting. Exercise offline user-image matching and verify both typed and YAML overrides.

### P1 Retry limits, cache validity and workspace ownership are incomplete

**Partially remediated.** Nine simulated keys with repeated JSON errors now produced six calls and 44 seconds of scheduled sleep, down from 655,355 seconds. A fake SDK call that returned after 120 seconds was still accepted against the advertised 90-second deadline. The timeout only governs attempts and sleeps around the call. Cloudflare now rejects corrupt data and normalizes valid JPEG responses to PNG. Gemini can still write inline bytes directly, and a successful PNG write is not atomic. The cache can hit a prior-theme image after another slide changes the single shared theme marker. Two cache writers that both read the same initial manifest lost the first worker's entry. Cache keys also omit provider, effective prompt additions and layout. Shared build filenames and directories permit one invocation to overwrite or delete another invocation's intermediate files. [Planner deadline](../../../ppt_maker/planning/planner.py#L456) · [Cloudflare write](../../../ppt_maker/imaging/image_generator.py#L443) · [Gemini write](../../../ppt_maker/imaging/image_generator.py#L467) · [Cache manifest](../../../ppt_maker/imaging/image_cache.py#L43) · [Build cleanup](../../../ppt_maker/cli.py#L453)

**Acceptance.** Pass remaining deadline into each provider call, record attempt and fallback reason, and apply a provider-level failure budget for repeated outages. Use per-run directories plus atomic shared-cache publication keyed by effective inputs and provider configuration. Validate every provider's image before publishing it and prove two concurrent test runs yield complete isolated artifacts. Preserve the uploading client or credential scope for media cleanup if planning rotates credentials.

### P1 Replay, theme assets and rendering trust need an explicit boundary

**Partially remediated.** All nine mapped texture paths resolve in checkout and installed wheel. Applying a different theme kept the prior theme's absolute texture URI in a replay probe. The installed CLI required an `init` step to replay a saved sample plan without an existing config. After `init`, it kept all 12 slides and changed the stored `glassmorphism` to `corporate_clean`. Theme tokens still accept general dictionary values that are rendered through Jinja's `safe` escape bypass. The current audit checks selected DOM containers for vertical overflow, and its image pass has limited visibility into the actual manifest and CSS background images. A visually busy theme background can pass. [Theme merge](../../../ppt_maker/design/theme_resolver.py#L156) · [CLI theme override](../../../ppt_maker/cli.py#L425) · [CSS rendering](../../../ppt_maker/templates/base.html#L57) · [DOM checks](../../../ppt_maker/rendering/renderer.py#L330) · [Audit image inputs](../../../ppt_maker/audit/quality_checker.py#L189)

**Acceptance.** Keep theme intent and portable asset IDs in the plan. Apply invocation overrides only when explicit. Allowlist recognized theme tokens and typed values, constrain user-supplied links to allowed schemes, and apply browser network policy before opening user-supplied content. Measure selected foreground and background contrast on rendered slides, and use a run manifest for user assets, generated assets, and theme imagery.

### P1 Refinement can report resolution without auditing the final slide

**Reproduced with a deterministic audit callback.** The callback always returned overflow. After the last-resort fallback the refiner returned `resolved=True` following only the earlier audit. Retry rendering rewrites the final HTML path with `total_slides=1`. The CLI then uses DOM results obtained before refinement for the inline quality report. An LLM patch returns a replacement `Slide`; beyond fixing the slide number, it can change citations and other semantics. [Refinement loop](../../../ppt_maker/planning/refiner.py#L279) · [Patch contract](../../../ppt_maker/planning/planner.py#L565) · [CLI audit cache](../../../ppt_maker/cli.py#L541)

**Acceptance.** Render changes in candidate files with real deck context, preserve evidence and notes visibility, and record an unresolved status when the last render fails. Publish only the chosen slide version. Feed the final audit from the exact artifacts that the CLI reports.

### P1 Evaluation and CI currently overstate verified quality

**Reproduced on synthetic fixtures.** The default benchmark returned nine wins and one tie and composites of 96.3 versus 95.0. The deterministic scorecard returned 90% pass rate. Benchmark winners can be selected on one score even when their composite is lower. The comparative run uses empty DOM results and fixed token counts, does not send `--model` to the planner constructors, and may substitute a synthetic plan if a live planner fails. The main runner can now construct a live planner, but still injects estimated tokens, leaves DOM measurements empty, and uses `--judge` to select live mode without wiring deck judging into that call. [Comparative runner](../../../evals/compare_pipelines.py#L196) · [Winner logic](../../../evals/compare_pipelines.py#L262) · [Main runner](../../../evals/run.py#L257) · [Judge flag](../../../evals/run.py#L394)

**Acceptance.** Record model and fallback provenance for each result. Use a declared tie rule and measure actual usage. Keep failed runs visible. An unrendered deck should have audit status `unmeasured`. Add a real CLI export job using fixtures that cover the Hero subtitle, reverse split, note confidentiality, and every expected artifact ID. Run these independently of fixture scoring. [CI](../../../.github/workflows/ci.yml)

## Additional maintainability and precision issues

- Headline and filler rules log warnings without changing all user-visible text. The density check reads only legacy bullets, and the code's threshold and warning text disagree. Move display constraints to a layout-aware validator with consistent feedback and checks for numeric precision. [Copy rules](../../../ppt_maker/planning/validator.py#L83)
- Native template discovery uses a developer-specific absolute directory. The native injector selects the largest text box rather than using known placeholder IDs and trims unused slides, which can also remove template attribution. Make template sources configurable and support explicit metadata for templates that may ship. [Template discovery](../../../ppt_maker/export/template_injector.py#L13) · [Shape heuristics](../../../ppt_maker/export/template_injector.py#L115)
- Test discovery still executes some legacy harness cases during import, and two CLI-oriented cases can return early when ignored artifacts are missing. Audit reports also conflate skipped checks with passes. Convert these cases to ordinary fixtures and distinguish `passed`, `failed`, and `skipped` in audit and CI output.
