# ISS-008 — glassmorphism gradient fallback images were near-white

**Severity:** MEDIUM  
**Status:** ✅ FIXED (2026-08-02)  
**Affects:** glassmorphism theme, all slides using gradient fallback images  
**Commit:** `theme_palettes.py` — `GRADIENT_FALLBACK_PRESETS['glassmorphism']` richer colours

---

## Symptom

When the API is rate-limited or offline and `ImageGenerator` falls back to the `GradientGenerator`, the glassmorphism theme produced gradient images that were almost indistinguishable from white:

```
slide_1.png: center=(240, 248, 255), brightness=247  ← near-white
slide_3.png: center=(240, 248, 255), brightness=247  ← near-white
```

Since the body background is also near-white (`--bg: #F7FAFC`, brightness 247), the gradient images provided zero visual uplift over a plain background.

---

## Root Cause

`GRADIENT_FALLBACK_PRESETS['glassmorphism']` in `theme_palettes.py` defined extremely pale colours:

```python
# BEFORE FIX
"glassmorphism": [
    ((240, 248, 255), (200, 220, 255), 135, "circles"),  # pale blue → paler blue
    ((255, 245, 240), (255, 220, 210), 135, "circles"),  # pale peach → paler peach
    ((240, 255, 245), (210, 245, 220), 135, "circles"),  # pale mint → paler mint
],
```

All three presets start at brightness ~246 and end at brightness ~230 — the colour range of the generated image is only ~16 points. Combined with the near-opaque cover overlay (ISS-005, also now fixed), the images were completely hidden.

### Root cause of the pale colours:

The presets were designed to complement a **light glassmorphism theme** (white body bg, white cards) where only a hint of colour tint in the background was needed. But after ISS-005 made the overlay more transparent, these barely-coloured images became the primary visual element — and they're too pale for that role.

---

## Fix Applied

```python
# AFTER FIX — theme_palettes.py
"glassmorphism": [
    # Glassmorphism needs RICH backgrounds so the frosted glass cards stand out.
    # Near-white gradients defeat the entire glass effect.
    ((40, 80, 160),  (80, 40, 140),  135, "circles"),  # deep blue → purple
    ((20, 100, 120), (60, 30, 100),  135, "circles"),  # teal → violet
    ((100, 40, 120), (40, 80, 160),  135, "circles"),  # magenta → blue
    ((30, 60, 100),  (60, 120, 80),  135, "circles"),  # navy → green
],
```

**Result:**
```
slide_1.png: center=(20, 100, 120), brightness=80   ← rich teal
slide_3.png: center=(20, 100, 120), brightness=80   ← rich teal
```

Brightness dropped from 247 → 80. Combined with the more transparent overlay (ISS-005), the cover slide Q-score went from ~5 → 85.

---

## Important Note

This fix only affects **gradient fallback images** (used when the API is unavailable). When the API successfully generates images (the normal case), the AI-generated images are used instead and are not affected by this change.

The gradient fallback images are generated by `GradientGenerator` in `gradient_generator.py`, seeded by `slide_number` for reproducibility. After this fix, the existing cached `.png` files needed to be regenerated:

```bash
python cli.py generate --offline-plan master_plan.json --clean-images
```

---

## Regression Risk

- The new dark gradient images may clash with **light themes** (editorial, corporate_clean) that also fall back to glassmorphism presets — but in practice, these themes use `GRADIENT_FALLBACK_PRESETS['editorial']` and `['corporate_clean']` respectively (not `glassmorphism`), so there is no conflict
- If the API returns AI-generated light/pastel images (which is common for glassmorphism prompts), they may now appear washed-out against the richer gradient fallbacks. Consider updating image prompts for glassmorphism to request darker, more saturated colours.
